## Linear Search

Linear search is the simplest approach: start at the beginning and check each element one by one until you find what you're looking for (or run out of elements).

```run-java
public class Main {

    static int linearSearch(int[] arr, int target) {
        for (int i = 0; i < arr.length; i++) {
            if (arr[i] == target) {
                return i;   // found — return the index
            }
        }
        return -1;          // not found
    }

    public static void main(String[] args) {
        int[] nums = {34, 12, 67, 8, 45, 23, 91, 5};

        System.out.println(linearSearch(nums, 45));    // 4
        System.out.println(linearSearch(nums, 99));    // -1
    }
}
```

**Key properties:**
- Works on any array — sorted or unsorted
- Returns `-1` as a sentinel value when not found
- Worst case: checks every element (when the target is last or not present)
- For an array of `n` elements, checks up to `n` elements

## Binary Search

Binary search is much faster — but it **requires a sorted array**. The idea: look at the middle element. If it's your target, done. If it's too big, the target must be in the left half. If it's too small, the target must be in the right half. Repeat on the appropriate half.

```run-java
public class Main {

    static int binarySearch(int[] arr, int target) {
        int low  = 0;
        int high = arr.length - 1;

        while (low <= high) {
            int mid = (low + high) / 2;

            if (arr[mid] == target) {
                return mid;             // found!
            } else if (arr[mid] < target) {
                low = mid + 1;          // target is in right half
            } else {
                high = mid - 1;         // target is in left half
            }
        }
        return -1;                      // not found
    }

    public static void main(String[] args) {
        int[] sorted = {5, 8, 12, 23, 34, 45, 67, 91};

        System.out.println(binarySearch(sorted, 45));   // 5
        System.out.println(binarySearch(sorted, 99));   // -1
    }
}
```

---

## Tracing Binary Search

Let's trace `binarySearch({5, 8, 12, 23, 34, 45, 67, 91}, 45)`:

| Step | low | high | mid | arr[mid] | Action |
|------|-----|------|-----|----------|--------|
| 1 | 0 | 7 | 3 | 23 | 23 < 45 → low = 4 |
| 2 | 4 | 7 | 5 | 45 | Found! Return 5 |

Linear search would have taken 6 comparisons. Binary search took 2.

## Efficiency Comparison

| Algorithm | Best Case | Worst Case | Requirement |
|-----------|-----------|------------|-------------|
| Linear Search | 1 comparison (found first) | n comparisons | None |
| Binary Search | 1 comparison (found at mid) | ~log₂(n) comparisons | **Sorted array** |

For 1,000 elements: linear search needs up to 1,000 checks; binary search needs at most 10.
For 1,000,000 elements: linear needs up to 1,000,000 checks; binary needs at most 20.

> [!NOTE] When to Use Which
> Use linear search when the array isn't sorted or when you only search once. Use binary search when you search a sorted array repeatedly — the speed advantage is enormous.

## 📌 Summary

- Linear search: check each element one by one; works on any array; returns `-1` if not found #searching #algorithm
- Binary search: requires a **sorted** array; eliminates half the search space each step #searching #algorithm #mc_only
- Binary search loop: maintain `low` and `high` pointers, compute `mid = (low + high) / 2` #searching #algorithm #pattern #mc_only
- For `n` elements, binary search needs at most `log₂(n)` comparisons vs `n` for linear #searching #concept #mc_only
- Use linear search for unsorted data or one-time searches; binary search for repeated searches on sorted data #searching #concept
