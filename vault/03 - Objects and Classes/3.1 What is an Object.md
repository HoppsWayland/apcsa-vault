## Objects vs Primitives

You already know the primitive types — `int`, `double`, `boolean`, `char`. They hold a single simple value, and that's it.

**Objects** are different. An object bundles together:
- **Data** (called *instance variables* or *fields*) — the information the object holds
- **Behavior** (called *methods*) — the things the object can do

You've actually been using objects all along. `String` is an object. When you write `"hello".toUpperCase()`, you're calling a method on a String object.

---

## A Real-World Analogy

Think about a bank account. A bank account has:
- **Data**: account number, owner's name, balance
- **Behavior**: deposit, withdraw, check balance

In Java, you'd represent that as an object. The *class* is the blueprint — it defines what all bank accounts look like. Each actual account is an *instance* of that class.

---

## References, Not Values

This is one of the most important concepts in Java. When you declare a primitive:

```java
int x = 5;
```

`x` *contains* the value 5. But when you declare an object variable:

```java
String name = "Alice";
```

`name` doesn't *contain* the String — it holds a **reference** (think: address) to where the String lives in memory. The variable points *to* the object.

This matters a lot when you have two variables pointing to the same object:

```java
String a = "hello";
String b = a;       // b points to the SAME object as a
```

---

## `null` — The Empty Reference

An object variable that doesn't point to anything holds the value `null`:

```java
String name = null;   // name exists but points to nothing
```

If you try to call a method on a `null` reference, Java throws a `NullPointerException` — one of the most common runtime errors you'll encounter:

```java
String name = null;
System.out.println(name.length());   // NullPointerException!
```

> [!TIP] Avoiding NullPointerExceptions
> Before calling a method on an object, you can check: `if (name != null)`. You'll develop a habit for this over time.

## Try It — References

```run-java
public class Main {
    public static void main(String[] args) {
        String s1 = new String("hello");
        String s2 = s1;    // s2 points to the same object

        System.out.println(s1.equals(s2));   // true — same content
        System.out.println(s1 == s2);        // true — same object!

        // Now give s2 a NEW object
        s2 = new String("hello");
        System.out.println(s1.equals(s2));   // still true — same content
        System.out.println(s1 == s2);        // false — different objects now
    }
}
```

## 📌 Summary

- Objects bundle **data** (instance variables) and **behavior** (methods) into one unit #objects #concept
- Object variables hold a **reference** (address), not the value itself #objects #concept
- Two variables can point to the same object — changing through one affects the other #objects #concept #gotcha
- `null` means a variable doesn't point to any object — calling methods on `null` throws `NullPointerException` #objects #gotcha
- `String` is an object — this is why `==` doesn't work for String comparison #strings #objects #concept
