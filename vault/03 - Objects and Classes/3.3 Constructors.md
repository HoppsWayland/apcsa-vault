## What's a Constructor?

A constructor is a special method that runs **automatically when you create an object with `new`**. Its job is to set up the object's initial state — giving the instance variables their starting values.

Constructors look like methods, but with two differences:
1. The name matches the class name exactly
2. No return type — not even `void`

```java
public class Student {
    private String name;
    private int grade;
    private double gpa;

    // Constructor
    public Student(String name, int grade, double gpa) {
        this.name  = name;
        this.grade = grade;
        this.gpa   = gpa;
    }
}
```

Now creating a Student requires passing in values:

```java
Student s = new Student("Alice", 11, 3.8);
```

---

## The `this` Keyword

Notice `this.name = name` in the constructor above. What's going on?

The parameter is called `name`, and the instance variable is *also* called `name`. Java needs a way to tell them apart. `this.name` refers to the **instance variable** (belonging to this object), while plain `name` refers to the **parameter**.

```java
public Student(String name, int grade, double gpa) {
    this.name  = name;    // this.name = the instance variable, name = the parameter
    this.grade = grade;
    this.gpa   = gpa;
}
```

`this` always means "the current object." It's how a method or constructor refers to itself.

> [!TIP] Avoiding the Confusion Entirely
> Some programmers name parameters differently (e.g. `n` instead of `name`) to avoid needing `this`. That works, but `this` is cleaner and more conventional — and it's explicitly tested on the AP exam.

## Try It — Constructor in Action

```run-java
public class Main {

    static class Student {
        private String name;
        private int grade;
        private double gpa;

        public Student(String name, int grade, double gpa) {
            this.name  = name;
            this.grade = grade;
            this.gpa   = gpa;
        }
    }

    public static void main(String[] args) {
        Student s1 = new Student("Alice", 11, 3.8);
        Student s2 = new Student("Bob",   10, 3.2);

        // We can't access private fields directly — but we can verify objects exist
        System.out.println("Created two students!");
        System.out.println(s1);   // Not very useful yet — we'll fix this in 3.5
        System.out.println(s2);
    }
}
```

The default output from `System.out.println(s1)` isn't very readable — that's what [[03 - Objects and Classes/3.5 toString|3.5 toString]] is all about.

## Multiple Constructors (Overloading)

A class can have more than one constructor, as long as they have different parameter lists. This is called **overloading**.

```java
public class Student {
    private String name;
    private int grade;
    private double gpa;

    // Full constructor
    public Student(String name, int grade, double gpa) {
        this.name  = name;
        this.grade = grade;
        this.gpa   = gpa;
    }

    // Constructor with just a name — grade and gpa get defaults
    public Student(String name) {
        this.name  = name;
        this.grade = 9;     // default: freshman
        this.gpa   = 0.0;
    }
}
```

Java figures out which constructor to call based on what arguments you pass:

```java
Student s1 = new Student("Alice", 11, 3.8);   // uses first constructor
Student s2 = new Student("Bob");               // uses second constructor
```

## 📌 Summary

- A constructor runs automatically when an object is created with `new` #constructors #concept
- Constructors have no return type (not even `void`) and must match the class name exactly #constructors #syntax
- `this.name = name` — `this.name` is the instance variable; `name` is the parameter #constructors #syntax #gotcha
- A class can have multiple constructors with different parameter lists (overloading) #constructors #concept
- If you forget `this.` when parameter names match instance variable names, the assignment does nothing #constructors #gotcha
