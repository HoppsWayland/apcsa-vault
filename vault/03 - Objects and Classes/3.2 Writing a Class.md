## The Structure of a Class

A class is a blueprint. Here's the skeleton:

```java
public class ClassName {

    // Instance variables (the data)
    private type variableName;

    // Constructor (covered next note)
    public ClassName(parameters) { ... }

    // Methods (the behavior)
    public returnType methodName(parameters) { ... }
}
```

Let's build a real example — a `Student` class:

```java
public class Student {

    // Instance variables
    private String name;
    private int grade;
    private double gpa;

    // (Constructor and methods to come)
}
```

---

## Instance Variables

Instance variables define the **data** that each object holds. Every `Student` object will have its own `name`, `grade`, and `gpa` — separate from every other `Student`.

They're declared at the top of the class, **outside** any method.

---

## Access Modifiers — `public` and `private`

You'll see `public` and `private` in front of variables and methods. Here's the rule of thumb:

- **`private`** — only accessible from within this class. Use this for instance variables. This protects your data from being changed accidentally from outside the class.
- **`public`** — accessible from anywhere. Use this for methods you want others to be able to call.

This pattern — private data, public methods — is called **encapsulation**. It's one of the core principles of OOP.

```java
public class Student {
    private String name;    // ← private: only Student's own methods can touch this
    private int grade;
    private double gpa;
}
```

From outside the class, you can't do this:
```java
Student s = new Student();
s.name = "Alice";           // ← COMPILE ERROR: name is private
```

You have to go through methods — which we'll add shortly.

> [!NOTE] Why Bother With private?
> Imagine a `BankAccount` class. If `balance` were public, any code anywhere could set it to any value: `account.balance = 1000000`. Making it private means the only way to change the balance is through `deposit()` and `withdraw()` — which can enforce rules like "you can't withdraw more than you have."

---

## Creating Objects — The `new` Keyword

Once a class is defined, you create objects (instances) using `new`:

```java
Student s1 = new Student();
Student s2 = new Student();
```

`s1` and `s2` are two separate objects, each with their own copies of `name`, `grade`, and `gpa`. Changing one doesn't affect the other.

---

## Try It — Two Objects, Independent Data

The class below has public instance variables (just for demonstration — we'll fix that with constructors and methods next):

```run-java
public class Main {

    static class Point {
        public int x;
        public int y;
    }

    public static void main(String[] args) {
        Point p1 = new Point();
        p1.x = 3;
        p1.y = 4;

        Point p2 = new Point();
        p2.x = 10;
        p2.y = 20;

        System.out.println("p1: (" + p1.x + ", " + p1.y + ")");
        System.out.println("p2: (" + p2.x + ", " + p2.y + ")");

        // Change p1 — does p2 change?
        p1.x = 99;
        System.out.println("After changing p1:");
        System.out.println("p1: (" + p1.x + ", " + p1.y + ")");
        System.out.println("p2: (" + p2.x + ", " + p2.y + ")");
    }
}
```

## 📌 Summary

- Instance variables are declared at the top of the class, outside any method #classes #syntax
- Make instance variables `private` — this is encapsulation #classes #concept
- Make methods `public` so they can be called from outside the class #classes #syntax
- Each object gets its own copy of instance variables — changing one object doesn't affect another #classes #concept
- Create objects with `new`: `Student s = new Student();` #classes #syntax
