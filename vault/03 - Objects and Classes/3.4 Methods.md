## What's a Method?

A method is a named block of code that belongs to a class. Methods define what objects can **do**. They can read data, change data, perform calculations, and interact with other objects.

Every method has a **signature** that tells you:
1. Who can call it (`public` / `private`)
2. What it returns (or `void` if nothing)
3. Its name
4. Its parameters (inputs)

```java
public double calculateGPA() { ... }
//     ^^^^^^ return type
//            ^^^^^^^^^^^^ name
//                        ^^ no parameters
```

---

## void Methods — Do Something, Return Nothing

A `void` method performs an action but doesn't return a value.

```java
public class Student {
    private String name;
    private int grade;
    private double gpa;

    // ...constructor...

    // void method — just prints, returns nothing
    public void printInfo() {
        System.out.println(name + " (Grade " + grade + ", GPA: " + gpa + ")");
    }

    // void method with a parameter — modifies data
    public void setGpa(double newGpa) {
        if (newGpa >= 0.0 && newGpa <= 4.0) {
            gpa = newGpa;
        }
    }
}
```

The `setGpa` method is called a **setter** — it sets the value of a private instance variable. Notice how it validates the input before accepting it — that's encapsulation doing its job.

---

## Return Methods — Compute and Return a Value

A method with a return type does some computation and hands a value back to the caller.

```java
public class Student {
    private String name;
    private double gpa;

    // ...

    // Getter — returns the value of a private field
    public String getName() {
        return name;
    }

    public double getGpa() {
        return gpa;
    }

    // Returns a computed value
    public boolean isHonorsEligible() {
        return gpa >= 3.5;
    }
}
```

Methods that just return the value of an instance variable are called **getters**. Since instance variables are private, getters are how outside code accesses them.

> [!NOTE] Getters and Setters
> The convention is `getName()`, `getGpa()` for getters and `setGpa(value)` for setters. You'll see this pattern constantly. Not every field needs both — a field that should never be changed from outside might only have a getter.

## Putting It All Together

```run-java
public class Main {

    static class Student {
        private String name;
        private int grade;
        private double gpa;

        public Student(String name, int grade, double gpa) {
            this.name  = name;
            this.grade = grade;
            this.gpa   = gpa;
        }

        public String getName()  { return name; }
        public int    getGrade() { return grade; }
        public double getGpa()   { return gpa; }

        public void setGpa(double newGpa) {
            if (newGpa >= 0.0 && newGpa <= 4.0) {
                gpa = newGpa;
            }
        }

        public boolean isHonorsEligible() {
            return gpa >= 3.5;
        }

        public void printInfo() {
            System.out.println(name + " | Grade " + grade + " | GPA: " + gpa);
        }
    }

    public static void main(String[] args) {
        Student s = new Student("Alice", 11, 3.8);
        s.printInfo();

        System.out.println("Honors eligible: " + s.isHonorsEligible());

        s.setGpa(3.2);
        System.out.println("After GPA update:");
        s.printInfo();
        System.out.println("Honors eligible: " + s.isHonorsEligible());

        // Try to set an invalid GPA
        s.setGpa(5.0);
        System.out.println("After invalid GPA attempt: " + s.getGpa());
    }
}
```

## Method Parameters — Passing Values

When you call a method with arguments, Java **copies** the value into the parameter. This means changes to a primitive parameter inside a method don't affect the original variable:

```run-java
public class Main {

    static void doubleIt(int x) {
        x = x * 2;
        System.out.println("Inside method: " + x);
    }

    public static void main(String[] args) {
        int num = 5;
        doubleIt(num);
        System.out.println("Outside method: " + num);   // still 5!
    }
}
```

## 📌 Summary

- `void` methods perform an action and return nothing; return methods compute and hand back a value #methods #syntax
- Getters (`getName()`) return the value of a private field; setters (`setName(v)`) update it #methods #pattern
- Setters can validate input before accepting it — this is encapsulation protecting data #methods #concept
- Primitive parameters are passed by value — changes inside a method don't affect the original variable #methods #concept #gotcha
- Every non-void method must have a `return` statement that matches the declared return type #methods #syntax #gotcha
