## What is Scope?

**Scope** is the region of code where a variable exists and can be used. Java has three levels of scope that you need to know:

| Scope | Where declared | Lives until |
|-------|---------------|-------------|
| **Class scope** | Inside the class, outside any method | The object is destroyed |
| **Method scope** | Inside a method (parameter or local variable) | The method returns |
| **Block scope** | Inside `{}` — an `if`, loop, etc. | The `}` is reached |

---

## Class Scope — Instance Variables

Instance variables are declared at the class level and are accessible from any method in the class:

```java
public class Student {
    private String name;    // class scope — accessible everywhere in Student
    private double gpa;

    public Student(String name, double gpa) {
        this.name = name;   // accessible here
        this.gpa  = gpa;
    }

    public void printInfo() {
        System.out.println(name + ": " + gpa);   // accessible here too
    }
}
```

---

## Method Scope — Parameters and Local Variables

Variables declared inside a method (including parameters) only exist while that method is running:

```java
public double calculateBonus(double salary) {
    double rate = 0.1;                   // local variable — only exists here
    double bonus = salary * rate;        // local variable
    return bonus;
}   // rate and bonus cease to exist here
```

Trying to use `rate` or `bonus` outside this method would be a compile error.

---

## Block Scope — Variables Inside {}

Variables declared inside a block (`if`, `for`, `while`, etc.) only exist within that block:

```java
for (int i = 0; i < 10; i++) {
    int doubled = i * 2;    // block scope — only exists inside this loop
    System.out.println(doubled);
}
// i and doubled don't exist here — compile error if you try to use them
```

This is why the loop variable `i` has to be declared in every new loop — it doesn't survive past its own `}`.

---

## Shadowing — When Names Collide

When a local variable has the same name as an instance variable, the local one **shadows** it — the instance variable is hidden unless you use `this`:

```java
public class Student {
    private String name = "Default";

    public void setName(String name) {
        // 'name' here refers to the PARAMETER, not the instance variable
        System.out.println(name);        // prints the parameter
        System.out.println(this.name);   // prints the instance variable
        this.name = name;                // assigns parameter → instance variable
    }
}
```

This is exactly the `this` pattern from constructors — same idea, same fix.

## Try It — Scope in Action

```run-java
public class Main {

    static class Rectangle {
        private double width;
        private double height;

        public Rectangle(double width, double height) {
            this.width  = width;
            this.height = height;
        }

        public double getArea() {
            double area = width * height;   // local variable
            return area;
        }

        public boolean isLargerThan(Rectangle other) {
            double myArea    = this.getArea();    // local
            double otherArea = other.getArea();   // local
            return myArea > otherArea;
        }
    }

    public static void main(String[] args) {
        Rectangle r1 = new Rectangle(5, 3);
        Rectangle r2 = new Rectangle(4, 4);

        System.out.println("r1 area: " + r1.getArea());
        System.out.println("r2 area: " + r2.getArea());
        System.out.println("r1 larger: " + r1.isLargerThan(r2));
    }
}
```

## Access Modifiers — `public` and `private`

Access modifiers control which code can see a member:

| Modifier | Accessible from |
|----------|----------------|
| `private` | Only within the same class |
| `public` | From anywhere |

The standard pattern in AP CSA:
- Instance variables → `private`
- Constructors → `public`
- Methods you want called from outside → `public`
- Helper methods only used internally → `private`

```java
public class BankAccount {
    private double balance;      // private — only this class can touch it

    public void deposit(double amount) {   // public — anyone can call
        if (isValidAmount(amount)) {       // calls private helper
            balance += amount;
        }
    }

    private boolean isValidAmount(double amount) {   // private helper
        return amount > 0;
    }
}
```

> [!TIP] Why Private Fields?
> If `balance` were public, any code anywhere could write `account.balance = -1000`. Making it private means the only way to change it is through `deposit()` and `withdraw()`, which can enforce rules. That's encapsulation.

## 📌 Summary

- **Class scope**: instance variables — accessible from any method in the class #classes #concept #syntax
- **Method scope**: parameters and local variables — exist only while the method runs #methods #concept #syntax
- **Block scope**: variables inside `{}` — exist only until the closing brace #loops #conditionals #concept #syntax
- Shadowing: a local variable with the same name as an instance variable hides it — use `this.` to reach the instance variable #classes #gotcha #constructors
- `private` instance variables protect data from outside modification — the core of encapsulation #classes #concept
- `public` methods are the controlled interface to an object's data #classes #concept
