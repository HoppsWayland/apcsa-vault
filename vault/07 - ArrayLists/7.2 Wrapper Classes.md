## Why Can't I Write `ArrayList<int>`?

Try it:

```java
ArrayList<int> numbers = new ArrayList<>();   // COMPILE ERROR
```

ArrayLists (and all Java generics) can only hold **objects**, not primitives. `int`, `double`, `boolean`, and `char` are not objects — they're primitive types.

So how do we make an ArrayList of numbers? We use **wrapper classes**.

---

## Wrapper Classes

Every primitive type has a corresponding wrapper class — an object version of that primitive:

| Primitive | Wrapper Class |
|-----------|--------------|
| `int` | `Integer` |
| `double` | `Double` |
| `boolean` | `Boolean` |
| `char` | `Character` |

```java
ArrayList<Integer> numbers = new ArrayList<>();   // correct!
ArrayList<Double>  prices  = new ArrayList<>();
ArrayList<Boolean> flags   = new ArrayList<>();
```

---

## Autoboxing and Unboxing

You might think using wrapper classes means lots of extra conversion code. It doesn't — Java handles it automatically.

**Autoboxing** — Java automatically converts a primitive to its wrapper when needed:
```java
ArrayList<Integer> nums = new ArrayList<>();
nums.add(42);       // Java autoboxes 42 (int) → Integer automatically
nums.add(17);
```

**Unboxing** — Java automatically converts a wrapper back to a primitive when needed:
```java
int x = nums.get(0);    // Java unboxes Integer → int automatically
```

In practice, you almost never have to think about this — Java does it for you transparently.

---

## Try It — Autoboxing in Action

```run-java
import java.util.ArrayList;

public class Main {
    public static void main(String[] args) {
        ArrayList<Integer> nums = new ArrayList<>();

        // Autoboxing — adding ints to an Integer list
        nums.add(10);
        nums.add(20);
        nums.add(30);

        // Unboxing — getting back an int
        int first = nums.get(0);
        System.out.println("First: " + first);

        // Math works naturally
        int sum = 0;
        for (int n : nums) {   // for-each unboxes automatically
            sum += n;
        }
        System.out.println("Sum: " + sum);
    }
}
```

## The `==` Trap With Wrapper Classes

Remember how `==` doesn't work for Strings? The same issue applies to wrapper classes. `==` compares references, not values.

```run-java
public class Main {
    public static void main(String[] args) {
        Integer a = 1000;
        Integer b = 1000;

        System.out.println(a == b);        // false — different objects!
        System.out.println(a.equals(b));   // true — same value
    }
}
```

> [!WARNING] Always Use .equals() for Wrapper Comparisons
> Just like with Strings, use `.equals()` to compare Integer, Double, and Boolean values. `==` will sometimes give surprising results.

---

## Useful Wrapper Class Methods

Wrapper classes come with some handy static methods:

```java
// Parsing strings to numbers
int x = Integer.parseInt("42");       // "42" → 42
double d = Double.parseDouble("3.14"); // "3.14" → 3.14

// Min and max values
System.out.println(Integer.MAX_VALUE);   // 2147483647
System.out.println(Integer.MIN_VALUE);   // -2147483648
```

`Integer.MAX_VALUE` and `Integer.MIN_VALUE` are useful for initializing min/max searches when you don't want to use the first array element.
