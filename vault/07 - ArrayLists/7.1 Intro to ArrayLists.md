## Why Not Just Use Arrays?

Arrays are fast and simple, but they have one big problem: **fixed size**. Once you create an array of size 10, it holds exactly 10 elements — no more, no less.

What if you're reading names from a file and you don't know how many there are? What if you need to add or remove items from the middle? An ArrayList handles all of this gracefully.

| | Array | ArrayList |
|---|---|---|
| Size | Fixed at creation | Grows and shrinks dynamically |
| Type | Primitives or objects | Objects only |
| Access | `arr[i]` | `list.get(i)` |
| Length | `arr.length` | `list.size()` |
| Add to end | Can't (unless pre-allocated) | `list.add(value)` |

---

## Creating an ArrayList

```java
import java.util.ArrayList;

ArrayList<String> names = new ArrayList<String>();
ArrayList<String> names = new ArrayList<>();   // shorthand — both work
```

The type in `<>` tells the ArrayList what kind of objects it holds. We'll cover why you can't write `ArrayList<int>` in [[07 - ArrayLists/7.2 Wrapper Classes|7.2 Wrapper Classes]].

---

## Basic Operations

```java
ArrayList<String> names = new ArrayList<>();

// Add to the end
names.add("Alice");
names.add("Bob");
names.add("Carol");

// Size
System.out.println(names.size());   // 3

// Access by index
System.out.println(names.get(0));   // "Alice"
System.out.println(names.get(2));   // "Carol"

// Modify by index
names.set(1, "Barbara");
System.out.println(names.get(1));   // "Barbara"
```

## Try It — ArrayList Basics

```run-java
import java.util.ArrayList;

public class Main {
    public static void main(String[] args) {
        ArrayList<String> fruits = new ArrayList<>();

        fruits.add("apple");
        fruits.add("banana");
        fruits.add("cherry");

        System.out.println("Size: " + fruits.size());
        System.out.println("Index 1: " + fruits.get(1));

        fruits.set(0, "avocado");
        System.out.println("After set: " + fruits.get(0));
        System.out.println("Full list: " + fruits);   // ArrayList has a nice toString!
    }
}
```

Notice that `System.out.println(fruits)` gives you `[apple, banana, cherry]` — ArrayLists have a built-in `toString()` that formats them nicely. Arrays don't have this, which is one quality-of-life reason to prefer ArrayLists.

---

## Adding at a Specific Index

```java
names.add(1, "Beth");   // inserts "Beth" at index 1, shifts everything right
```

Everything from index 1 onward shifts up by one. The list grows by one element.

---

## Removing Elements

```java
names.remove(0);            // removes element at index 0, shifts left
names.remove("Carol");      // removes first occurrence of "Carol" by value
```

> [!WARNING] remove(int) vs remove(Object)
> `remove(0)` removes by index. `remove("Carol")` removes by value. For an `ArrayList<Integer>`, this gets tricky — more on that in 7.3.

## 📌 Summary

- ArrayLists are resizable; arrays are fixed — use ArrayList when the size isn't known in advance #arraylists #concept
- ArrayLists can only hold objects, not primitives — use wrapper classes for numbers #arraylists #concept #gotcha
- `list.size()` not `list.length` — a classic mix-up #arraylists #gotcha
- `list.get(i)` not `list[i]` — another classic mix-up from arrays #arraylists #gotcha
- `add()`, `get()`, `set()`, `remove()`, `size()` — the core five methods #arraylists #syntax
- `System.out.println(list)` gives nicely formatted output — arrays don't do this #arraylists #concept
