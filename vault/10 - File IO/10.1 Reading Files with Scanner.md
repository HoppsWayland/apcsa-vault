## From Keyboard to File

You already know how to read from the keyboard:

```java
Scanner scanner = new Scanner(System.in);   // reads from keyboard
```

Reading from a file is the same class — just a different source:

```java
Scanner scanner = new Scanner(new File("data.txt"));   // reads from file
```

The methods (`nextLine()`, `nextInt()`, `hasNext()`, etc.) are identical — only the setup changes.

---

## The Full Setup

```java
import java.util.Scanner;
import java.io.File;
import java.io.FileNotFoundException;

public class ReadFile {
    public static void main(String[] args) throws FileNotFoundException {
        File file = new File("data.txt");
        Scanner scanner = new Scanner(file);

        while (scanner.hasNextLine()) {
            String line = scanner.nextLine();
            System.out.println(line);
        }

        scanner.close();
    }
}
```

A few new things here:

**`import java.io.File`** — you need this import to use the `File` class.

**`throws FileNotFoundException`** — if the file doesn't exist, Java throws this exception. Adding `throws FileNotFoundException` to the method signature tells Java "I know this might fail — let it bubble up." The AP exam expects you to know this is required.

**`scanner.close()`** — good practice to close the scanner when done. Frees the file resource.

## Scanner Methods for Files

All the same methods work — plus these are especially useful for files:

| Method | Returns | Use when |
|--------|---------|----------|
| `hasNextLine()` | `boolean` | You want to read line by line |
| `nextLine()` | `String` | Reading a full line |
| `hasNext()` | `boolean` | More tokens remain (any type) |
| `hasNextInt()` | `boolean` | The next token is an int |
| `nextInt()` | `int` | Read the next integer |
| `hasNextDouble()` | `boolean` | The next token is a double |
| `nextDouble()` | `double` | Read the next double |

> [!NOTE] All of These Are on the AP Quick Reference
> The file-reading Scanner methods are explicitly listed on the 2025-26 Java Quick Reference sheet. You'll have them on exam day.

---

## The `hasNextLine()` Pattern

Read every line until the file ends:

```java
while (scanner.hasNextLine()) {
    String line = scanner.nextLine();
    // process line
}
```

## The `hasNext()` Pattern

Read token by token (whitespace-separated) until the file ends:

```java
while (scanner.hasNext()) {
    String word = scanner.next();
    // process word
}
```

## The `hasNextInt()` Pattern

Read integers, skipping non-integer tokens:

```java
while (scanner.hasNextInt()) {
    int num = scanner.nextInt();
    // process num
}
```

## Try It — Reading a File

This example creates a file and reads it back (using the Linux filesystem available in your Linux environment):

```run-java
import java.util.Scanner;
import java.io.File;
import java.io.FileWriter;
import java.io.FileNotFoundException;

public class Main {
    public static void main(String[] args) throws Exception {
        // Create a sample file to read
        FileWriter fw = new FileWriter("sample.txt");
        fw.write("Alice 95\n");
        fw.write("Bob 82\n");
        fw.write("Carol 91\n");
        fw.write("Dave 78\n");
        fw.close();

        // Now read it back
        Scanner scanner = new Scanner(new File("sample.txt"));

        while (scanner.hasNextLine()) {
            System.out.println(scanner.nextLine());
        }

        scanner.close();
    }
}
```

## The `nextInt()` + `nextLine()` Trap — Again

You saw this with keyboard input in [[01 - Java Fundamentals/1.4 Input with Scanner|1.4]]. The same trap exists with files. After calling `nextInt()`, a newline character is left in the buffer. The fix is the same: call `scanner.nextLine()` to consume the leftover newline before reading the next full line.

## 📌 Summary

- File Scanner setup: `Scanner sc = new Scanner(new File("data.txt"));` — requires `import java.io.File;` #file-io #scanner #syntax
- Method signature must include `throws FileNotFoundException` or it won't compile #file-io #syntax #gotcha
- `hasNextLine()` / `nextLine()` for line-by-line reading; `hasNext()` / `next()` for token-by-token #file-io #scanner #syntax
- `hasNextInt()` / `nextInt()` for reading numeric data #file-io #scanner #syntax
- The `nextInt()` + `nextLine()` buffer trap applies to files too — flush with an extra `nextLine()` #file-io #scanner #gotcha
- Always call `scanner.close()` when done #file-io #syntax
