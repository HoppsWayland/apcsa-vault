## The Big Rule: Never Use `==` to Compare Strings

This is one of the most important rules in Java, and breaking it causes bugs that are genuinely hard to track down.

`==` checks whether two variables point to the **exact same object in memory**. For Strings, you almost always want to check whether two Strings have the **same content** — which is what `.equals()` does.

```java
String a = "hello";
String b = "hello";

System.out.println(a == b);        // might be true, might be false — unreliable!
System.out.println(a.equals(b));   // true — always correct
```

> [!WARNING] Why `==` Sometimes Seems to Work
> Java optimizes by reusing String objects for string literals, so `==` sometimes returns `true` by coincidence. But the moment you get a String from user input, a file, or any computation, `==` will fail. Never rely on it. **Always use `.equals()`.**

## `equals(String other)`

Returns `true` if the two Strings have identical content (case-sensitive).

```java
String s1 = "Java";
String s2 = "Java";
String s3 = "java";

System.out.println(s1.equals(s2));   // true
System.out.println(s1.equals(s3));   // false — different case
```

For case-insensitive comparison, combine with `toLowerCase()`:
```java
System.out.println(s1.toLowerCase().equals(s3.toLowerCase()));   // true
```

## `compareTo(String other)`

Compares two Strings **lexicographically** (alphabetical order, based on Unicode values). Returns:
- A **negative number** if this String comes before `other`
- **0** if they are equal
- A **positive number** if this String comes after `other`

```java
System.out.println("apple".compareTo("banana"));   // negative (a < b)
System.out.println("banana".compareTo("apple"));   // positive (b > a)
System.out.println("apple".compareTo("apple"));    // 0 (equal)
```

You don't need to know the exact number returned — just whether it's negative, zero, or positive.

> [!NOTE] Uppercase vs Lowercase
> In Unicode, all uppercase letters come before all lowercase letters. So `"Z".compareTo("a")` is **negative** — `'Z'` has a smaller Unicode value than `'a'`. When in doubt, convert both to the same case before comparing.

## Putting It Together — String Processing

Here's a realistic example that uses several String techniques together:

```run-java
public class Main {
    public static void main(String[] args) {
        String email = "Alice.Smith@School.EDU";

        // Normalize to lowercase
        String lower = email.toLowerCase();

        // Check it looks like an email
        boolean hasAt = lower.indexOf("@") != -1;
        System.out.println("Has @ sign: " + hasAt);

        // Extract parts
        int atIndex = lower.indexOf("@");
        String username = lower.substring(0, atIndex);
        String domain   = lower.substring(atIndex + 1);

        System.out.println("Username: " + username);
        System.out.println("Domain:   " + domain);

        // Compare
        System.out.println("Is school email: " + domain.equals("school.edu"));
    }
}
```

## 📌 Summary

- **Never use `==` to compare Strings** — use `.equals()` #strings #gotcha
- `==` checks if two variables point to the same object; `.equals()` checks content #strings #concept
- `equals()` is case-sensitive: `"Java".equals("java")` → `false` #strings #gotcha
- For case-insensitive comparison: `s1.toLowerCase().equals(s2.toLowerCase())` #strings #pattern
- `compareTo()` returns negative/0/positive for before/equal/after alphabetically #strings #syntax #algorithm
- Uppercase letters come before lowercase in Unicode — `"Z".compareTo("a")` is negative #strings #gotcha
