## What's a Boolean Expression?

A boolean expression is any expression that evaluates to either `true` or `false`. These are the conditions that drive every `if` statement and every loop.

---

## Comparison Operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `==` | Equal to | `x == 5` |
| `!=` | Not equal to | `x != 0` |
| `<` | Less than | `age < 18` |
| `>` | Greater than | `score > 90` |
| `<=` | Less than or equal | `grade <= 12` |
| `>=` | Greater than or equal | `gpa >= 3.5` |

> [!WARNING] `==` for Primitives Only
> `==` works correctly for primitive types (`int`, `double`, `boolean`). For objects — including Strings — you must use `.equals()`. This was covered in [[02 - Strings/2.3 String Comparisons|2.3 String Comparisons]] and it's worth remembering every time you write a condition.

---

## Logical Operators

Logical operators combine boolean expressions:

| Operator | Meaning | True when... |
|----------|---------|-------------|
| `&&` | AND | **Both** sides are true |
| `\|\|` | OR | **At least one** side is true |
| `!` | NOT | The expression is false |

```java
int age = 16;
boolean hasLicense = true;

System.out.println(age >= 16 && hasLicense);    // true — both true
System.out.println(age >= 18 || hasLicense);    // true — one is true
System.out.println(!hasLicense);                // false — flips it
```

---

## Short-Circuit Evaluation

Java is lazy — in a smart way. For `&&`, if the left side is `false`, Java doesn't even check the right side (the result must be `false` regardless). For `||`, if the left side is `true`, the right side is skipped.

This matters when the right side might cause an error:

```java
String s = null;
if (s != null && s.equals("hello")) {   // safe — if s is null, second part is skipped
    System.out.println("match");
}
```

If it were `s.equals("hello") && s != null`, you'd get a NullPointerException.

---

## De Morgan's Laws

De Morgan's Laws describe how to distribute `!` across `&&` and `||`. They come up on the AP exam:

```
!(a && b)  is the same as  !a || !b
!(a || b)  is the same as  !a && !b
```

In plain English:
- "NOT (both A and B)" = "either not-A, or not-B"
- "NOT (A or B)" = "neither A nor B"

```java
// These two conditions are equivalent:
!(x > 5 && y < 10)
x <= 5 || y >= 10
```

## Operator Precedence for Booleans

Within a boolean expression, the evaluation order is:
1. `!` (NOT) — highest
2. `&&` (AND)
3. `||` (OR) — lowest

```java
true || false && false    // true  (AND evaluated first: false&&false=false, then true||false=true)
(true || false) && false  // false (parentheses override)
```

When in doubt, use parentheses to make your intent clear.

---

## 📌 Summary

- Relational operators `==`, `!=`, `<`, `>`, `<=`, `>=` always evaluate to `true` or `false` #booleans #syntax
- Use `==` for primitives only — use `.equals()` for objects and Strings #booleans #gotcha #strings
- `&&` (AND) requires both sides true; `||` (OR) requires at least one; `!` (NOT) flips the value #booleans #syntax
- Short-circuit: `&&` stops at first `false`; `||` stops at first `true` — safe for null checks #booleans #concept #pattern
- De Morgan's Laws: `!(a && b)` → `!a || !b`; `!(a || b)` → `!a && !b` #booleans #algorithm #mc_only
- Precedence: `!` first, then `&&`, then `||` — use parentheses to be explicit #booleans #gotcha
