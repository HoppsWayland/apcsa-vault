## Recursive Binary Search

You already implemented binary search iteratively in [[08 - Searching and Sorting/8.1 Linear and Binary Search|8.1]]. It can also be written recursively — and comparing the two versions is a great way to see how recursion and iteration relate.

```run-java
public class Main {

    static int binarySearch(int[] arr, int target, int low, int high) {
        if (low > high) return -1;          // base case: search range is empty

        int mid = (low + high) / 2;

        if (arr[mid] == target) return mid; // base case: found it!
        if (arr[mid] < target) {
            return binarySearch(arr, target, mid + 1, high);  // search right half
        } else {
            return binarySearch(arr, target, low, mid - 1);   // search left half
        }
    }

    public static void main(String[] args) {
        int[] sorted = {5, 8, 12, 23, 34, 45, 67, 91};

        System.out.println(binarySearch(sorted, 45, 0, sorted.length - 1));   // 5
        System.out.println(binarySearch(sorted, 99, 0, sorted.length - 1));   // -1
    }
}
```

**The two base cases:**
- `low > high` — the range collapsed to nothing; target not found → return -1
- `arr[mid] == target` — found it → return mid

**The recursive cases:**
- Target is larger → search the right half (`mid+1` to `high`)
- Target is smaller → search the left half (`low` to `mid-1`)

## Tracing Recursive Binary Search

`binarySearch({5,8,12,23,34,45,67,91}, 45, 0, 7)`:

```
call 1: low=0, high=7, mid=3, arr[3]=23   23 < 45 → search right
call 2: low=4, high=7, mid=5, arr[5]=45   found! → return 5
```

## Merge Sort — The Concept

Merge sort is a recursive sorting algorithm that's much faster than selection or insertion sort for large datasets. You don't need to implement it for the AP exam, but you should understand the idea.

**The strategy: divide and conquer**
1. Split the array in half
2. Recursively sort each half
3. Merge the two sorted halves back together

```
mergeSort({5, 2, 8, 1, 9, 3})
├── mergeSort({5, 2, 8})
│   ├── mergeSort({5})         → {5}
│   ├── mergeSort({2, 8})
│   │   ├── mergeSort({2})     → {2}
│   │   ├── mergeSort({8})     → {8}
│   │   └── merge({2},{8})     → {2, 8}
│   └── merge({5},{2,8})       → {2, 5, 8}
├── mergeSort({1, 9, 3})
│   ├── ...similar...          → {1, 3, 9}
└── merge({2,5,8},{1,3,9})    → {1, 2, 3, 5, 8, 9}
```

The base case is an array of size 1 (already sorted). Everything else is split, sorted recursively, and merged.

> [!NOTE] Why is Merge Sort Faster?
> Selection and insertion sort are O(n²) — doubling the input roughly quadruples the work. Merge sort is O(n log n) — much more efficient for large inputs. For the AP exam, understanding this conceptually is enough.
